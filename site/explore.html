Use it as a benchmark

Bring an editor, score it on seeds it never saw.

The harness gives an editor (Claude Code or Codex CLI) one tool, owsp, to read weights, capture activations on exact recorded inputs and run paired practice rollouts; an operator then scores its single submitted edit on held-out seeds with an exact McNemar test.

# GPU host (Linux): pinned dependencies, weights, smoke test
git clone https://github.com/adeeb10abbas/weightsmith && cd weightsmith
scripts/setup_deps.sh
cp .env.example wsp.env          # paste the paths setup_deps.sh prints
scripts/prepare_workspace.sh     # editable weight export, ~11 GB
scripts/smoke_test.sh            # 16 episodes + 1 activation capture

# a task project and an editor
scripts/new_project.py --config configs/cube-then-banana.json \
    --root $ROOT --brief briefs/cube-then-banana/BRIEF.md \
    --agent-dir agents/my-editor
WSP_ROOT=$ROOT drivers/claude.sh agents/my-editor   # or drivers/astra.sh

# operator only: held-out paired evaluation of the submitted edit
WSP_ROOT=$ROOT python3 weightsmith/heldout.py --cand NAME --slot-start 90000 --n 192

  • Comparing editors: matched briefs, budgets and seeds for a head-to-head run.

  • An open target. The binding fix on cube-then-banana was built by an operator session under the editor rules, not by an autonomous editor. Whether an editor finds it on its own is untested.
