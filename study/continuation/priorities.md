# Priorities after this frozen study

These are proposed follow-up experiments, not changes to the completed discovery runs or running final controls. The current null result is bounded: no candidate passed the engineering gate. It does not establish that sparse editing cannot help, that the edits had zero effect, or that one editor/search mode is superior.

1. **Establish a repeatability reference before another edit search.** Save and compare the full simulator reset state (object poses and velocities, robot state, camera transforms, scene randomization and relevant RNG states), plus the actual first policy images and packet membership. Our current audit covers recorded robot state, seeds and camera inputs, not all of those hidden conditions. Separate repeated inference on an identical packet from repeated simulation after reset. A matching seed alone is not an identical trial.
2. **Correct and validate semantic feedback in a new runtime version.** The existing proposed annotation patch is not applied to either frozen study. Verify event arguments against scene objects on a successful rollout and representative failures, while checking that task-success Booleans remain on their separate path. Do not rewrite archived logs or retrospectively reclassify editor evidence.
3. **Retain the fixed16 full-packet replay contract.** Check native repeat, unchanged-weight load and instrumented-versus-native parity before using a capture. Report logical requests, real packet positions and padded forwards separately. Passing numerical replay validates those measurements; it does not make a success/failure activation contrast causal.
4. **Calibrate a future preservation rule using repeated unchanged-policy runs.** Keep this study's gate unchanged in the report. In a new preregistered experiment, use a separate calibration cohort to estimate ordinary breakage and success variability, then choose a practical preservation margin and a comparison method before seeing candidate outcomes. Account for shared environment execution and repeated references; do not treat action rows or repeated role labels as independent trials.
5. **Test a small set of explicit hypotheses with matched evidence.** Distinguish a nonzero weight intervention from a no-edit abstention and from gripper postprocessing. Use a fresh, identical common evidence package, log each hypothesis and actual bfloat16 changes, and separate development selection from final evaluation. For the editor comparison, give the teammate only the model-neutral handoff and common baseline, not this review package or Astra's outcomes. Record exact provider model/version, effort, tools and all-attempt costs.

A sensible next milestone is a reproducible unchanged-policy control and one interpretable intervention with a measured fixed-input effect, followed by an independently evaluated closed-loop comparison. Expanding to multiple manipulation tasks or claiming a self-improvement loop before those checks would overstate what the current setup measures. A non-flat proposal curve is not an improvement curve when the accepted policy never changes.

No additional jobs are launched by this document. The final gripper/repeat controls and separate resource diagnostics complete the frozen execution scope.

The [Guo–Xie addendum](../review/guo-xie.md) motivates testing task-trained checkpoints, recurring failure modes, and an audited attention interface alongside the existing MLP-only interface. These are proposed ablations; the social report does not establish which difference explains their positive outcomes. A matched reproduction requires the exact task/checkpoint/edit artifacts, which were not located in the inspected sources.


## Policy family and failure mechanism: pending teammate extension

The teammate reports preliminary observations that policy category and control-versus-perception failure type may affect editability. Numerical results and artifacts have not yet been supplied, so these are motivating hypotheses, not measured findings in the present paper. Stratify state-input controllers, VLAs and WAMs by the actual architecture and editable interface; the labels can overlap. Within each feasible policy/task, distinguish a localized motor failure from perceptual ambiguity and missing competence using validated diagnostics. Match prior task training, allowed probes, edit support, and discovery budget where possible. Report confounds rather than treating differences between unrelated tasks as a causal policy-family effect. Preserve clean editor contexts for any future Astra/Opus comparison.
